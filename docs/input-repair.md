# 桌面与触屏操作修复 · 2026-11-28

用户反馈：“除了点击按钮以外的全部，都有一端是无法使用的”。之前新增的RTS输入模块把桌面改为左键选兵、右键下令、中键镜头，触屏继续依赖鼠标模拟；操作入口和说明没有同步覆盖两端。此前触屏回归主要覆盖按钮、双指缩放和单栋建筑，遗漏了部队调动、单指拖动、停止、攻击移动、路点及城墙拖线。

改动位于未提交的 `game/scripts/rts_controls.gd` 及相关界面文件，Git不能归属到具体会话。上一轮交付把这套工作树改动一起打包，不能用“测试脚本通过”代表整套操作可用。

## 当前操作

| 动作 | 鼠标/键盘 | 触屏 |
| --- | --- | --- |
| 镜头平移 | 右键拖动、中键拖动、方向键、边缘 | 单指拖动；双指平移 |
| 缩放/旋转 | 滚轮、Q/E；地图面板按钮 | 双指缩放；地图面板按钮 |
| 选择/多选 | 左键、拖框、Shift增选、双击同类 | 点部队；点“框选”后拖出选框 |
| 移动 | 右键短按落点 | 选中后点落点 |
| 停止 | S | 选中栏“停止” |
| 攻击移动 | A后左键 | 选中栏“攻击”后点落点 |
| 追加路点 | Shift右键 | 开启“路点”后点后续落点 |
| 放置建筑 | 左键放置；R转向 | 点地面预览、转向、确认营造 |
| 城墙/油壕 | 左键拖线松开建设 | 单指拖线，确认营造 |
| 取消 | 右键/Esc；UI取消 | UI取消/取消选择 |

原生触摸事件由 `touch_controls.gd` 处理，鼠标模拟仅服务按钮，避免一次操作走两个世界输入路径。两指介入会取消待提交建筑/选框；释放、touchCancel、失焦、暂停和窗口变化均清理手势。建造确认前不扣资源。

布局按窗口宽高适配，输入方式依据实际事件；窄桌面窗口仍保留鼠标操作。紧凑地图与资源定位分成两个面板，使地图拖动与列表滚动不再争用同一区域；镜头按钮完整位于面板内。

Dora原生复测发现鼠标桥转发事件不可靠携带Shift标志，现同时读取真实按键状态；修复覆盖队列命令、组合选择及小地图命令。只读观测按Dora单字段512字节限制缩小，不能使用截断JSON作为测试结果。

## 验证

- `scripts/check-input-platforms.py`：真实鼠标/原生触摸事件，桌面1280×720、窄窗口844×390、触屏844×390、390×844和1280×800。检查单/双指镜头、取消、选兵、实际移动、停止、路点、攻击、框选、旋转、营造确认、拖线与取消；读取状态而不修改游戏。
- `scripts/check-input-dora.py`：Dora真实鼠标/键盘桥，镜头拖动与释放、招募选中、下令与实际移动、停止、框选、Shift路点、攻击移动及旋转。
- `scripts/check-h5.py`：菜单、建造扣费、拆除、募兵、存档入口、暂停、触屏及浏览器错误回归。
- 复现与过程证据位于 `.build/control-repair/`，最终结果以所记录的PCK哈希为准。浏览器触摸模拟不等于物理手机或Dora移动设备验收。
