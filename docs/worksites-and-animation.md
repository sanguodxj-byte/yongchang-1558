# 民丁、运输设施与模型净空 · 2026-11-27

本轮对应要求：修复模型相交，恢复单位骨骼动作，按工种持工具，允许建设堆放场，并把采石场与增产用的绑牛桩分离。正式实现仍为共同 Godot 工程，Dora/H5 使用相同 PCK。

## 工种与动作

模型导出器原来只记录直接子节点引用；人物手脚实际位于身体组内，导致导出的关节引用缺失。现在保存跨层级路径与关节数组，加载时校验路径。`unit_rig.gd` 在原模型上建立15骨骼的 `Skeleton3D`，保留低模外观，包含肩、肘、髋、膝、脚掌、头和手部挂点。后续精修的落脚、握持和工作接触规则见 [动作精修](motion-polish.md)。

步兵与宗长具有行走、待机、攻击动作，骑兵保留骑姿并驱动马腿；冲车撞木、炮车炮管、车轮和牛腿随状态运动。民丁采集、加工、搬运采用不同姿态。工具挂在右手骨骼，搬运时收起；暂停使用同一游戏时钟。

## 堆放场与绑牛桩

| 建筑 | 费用 / 占地 | 行为 |
| --- | --- | --- |
| 物资堆放场 | 8木、4石 / 2×2 | 收存木石铁油，按可达路线选择最近的堆场边缘入口；全封闭的堆场不收货。工坊取原料也使用可达堆场。 |
| 采石场 | 10木 / 1×1，靠近矿藏 | 石匠采集加工，每批6石，自行搬运入库；不附赠牛车。 |
| 水牛绑牛桩 | 12木、25银 / 2×2 | 绑定7格内一座可达采石场，每批产出9石（+50%），配一辆牛车，每次装载最多12石；不占民丁人口。 |

每座石场只接受一个绑牛桩，不叠加。石料先进入石场缓冲堆，牛车取货并实际送到堆场后才增加资源。拆除绑牛桩停止增产与对应牛车，石匠恢复手运；多余绑牛桩在没有可绑定石场时不额外生成牛车。运量和最终入库速度还受路程、拥堵影响，+50%是每批生产量。

新增堆场可拆除，返还一半木石；开局堆场保留为初始基础设施。它原来只是静态装饰，现在具有真实2×2占地和运输身份，并移除重复静态模型。新建筑画像由实际模型导出。预览与落地共用占地、资源、树木、矿点、高差和地形验证。

## 本轮修复的相交

- 采石场移除绑牛桩和饮水槽，改为石工台；绑牛设施使用独立模型。
- 农田水车移到屋檐外，水车与屋顶水平净距约0.255格；轮辐改为正确径向。
- 岛寨瞭望台棚顶提高，站立铳手头顶至棚布最小净空约0.436格。
- 南侧索具仓棚东移2格，与岸炮模型分离；双重防线仍保持闭合。
- 调整船上座位、物资位置，避开船尾舱与桅杆；单位分离处理纳入民丁和牛车，并处理完全同坐标情况。

这些是具体模型和路径修正，不能外推为所有地图布局、所有动作帧的零穿插保证。木栅与瞭望台的结构连接保留。

## 验证入口

`python scripts/check-worksites.py` 检查建造扣费、2×2占地、封闭堆场、开口恢复、独立采石、增产、不叠加、拆除恢复、骨骼姿态和七工种手部工具。240秒相同场景的实际入库增量为独立石场48石、带牛桩81石。该对照预置建造资金，只统计真实生产与运输增量，不作为正常经济通关证据。

`python scripts/check-model-clearance.py` 从实际导出顶点测量水车、棚顶与炮台净空和新增建筑占地。以 `.build/worksites/before/game/assets` 为输入时，相同检测能拒绝旧模型。

`python scripts/check-worksites-runtime.py` 通过真实H5输入建设采石场、绑牛桩、堆场、农田、伐木坊，检查牛车入库、三工种动作变化、工具、暂停与运行错误。`game/tests/worksites-visual.gd` 单独渲染七工种与各兵种的36帧模型检视，属于动作素材验收，不能代替正常战局试玩。

本轮证据目录为 `.build/worksites/`；最新运行包的验证结果与限制见 [双平台验收](platform-validation.md)。

完整H5经济回归使用真实输入完成25次建设、19次付费招募，353秒反攻、45人登陆、467.9秒胜利，无浏览器错误；证据在 `fortress/live-economy/`。该场没有预置资源或兵力；新绑牛桩与堆场则由前述专项真实输入单独覆盖。
