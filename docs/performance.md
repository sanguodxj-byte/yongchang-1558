## 本轮改动与结论

完成骨骼索引/骨长缓存、直接计算关节相对旋转、静止姿态与相同模拟时刻复用、无变化场景变换跳过、单位避让空间桶，以及按阵营和ID查询。保留原模型、4× MSAA、阴影、单位数量、动作参数及玩法规则。当前后续加入的存档、矿点导航、紧凑界面和训练开局均保留。

在当前版本上重新制作只撤去上述热路径优化的基线，执行A/B/A/B。六个场景的完整存档序列化哈希在采样起止均相同，包括单位位置、路径、生命值、计时器和实体关联；镜头、渲染尺寸与画质也相同。索引维护在基线中保留，以兼容当前存档，测量的是查询、避让和骨骼热路径节省。

平均脚本成本减少46%–86%。整帧尾部仍受负载和个别尖峰影响，不能据此宣布所有场景稳定60FPS。生产场景P95有所变慢，长帧保留在下表和原始数据中。

## 测量方法

- i5-12400F，6核12线程；RTX 4060 Ti 8GB，NVIDIA 581.80；Windows / Godot 4.7.2 / Edge 158硬件WebGL 2。
- 原生1280×800窗口，逻辑画布1600×1000，垂直同步与上限关闭。固定1/60秒引擎步长，每场480帧预热、600帧采样，每版两轮。固定步长只作用于压力夹具，正式游戏按真实时间运行。
- 采样来自游戏分段计时与RenderingServer.frame_post_draw；覆盖模拟、镜头、画面同步与HUD。已用8毫秒延迟验证归因与渲染帧编号递增。渲染回调间隔不是GPU耗时或物理显示器呈现时间。
- 计时期间无图像读回、录制、并行构建或其他验收。每秒记录总CPU、游戏CPU/RSS及竞争进程。共享机器，未获得逐帧GPU计时。
- 生产、军队、交战、全景、暂停为明确注入资源/部队的夹具；交战提高生命值维持负载。普通村落不注入。夹具不能代表正常经济过程。

真实手机、Safari、45–60分钟内存与帧尾稳定性、物理显示器呈现和逐帧GPU计时未验收。当前结论是CPU热路径优化与功能回归通过，重战场绘制成本和零星长帧仍有优化空间。
